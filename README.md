# 정배열 스크리너 ver2.1 — 경량 웹 재설계

앱이 아니라 웹입니다. **스캔은 새벽에 배치가 혼자 하고, 웹은 결과를 읽어서 차트만
보여줍니다.** 메일은 종목 리스트만 옵니다.

## 이번에 무엇을 바꿨나

| | ver0.4까지 | 재설계 후 (ver1.x) |
|---|---|---|
| 웹의 역할 | 스캔 실행 + 진행률 + 3탭 + 국면 스트립 | **목록 조회 + 차트만** |
| 스캔 실행 주체 | 웹서버 (버튼 클릭 / 백그라운드 스레드) | **daily_scan.py (cron) 뿐** |
| 웹 API | 6개 (`/api/scan`, `/api/status`, `/api/exits` 등) | **2개** (`/api/list`, `/api/chart/<code>`) |
| 메일 내용 | 사유·점수·이격도까지 담은 상세 리포트 | **종목명·코드·가격·등락률만** |
| 웹서버를 켜 둬야 하는 시간 | 스캔이 오래 걸리는 동안 계속 | **차트 보고 싶을 때만 잠깐** |

판정 로직(`screener.py`, `collector.py`, `datastore.py`, `pipeline.py`)은 그대로
가져왔습니다. 이미 단위 테스트 17건으로 검증된 부분이라 다시 만들 이유가 없었습니다.
바뀐 건 **서버와 화면, 그리고 메일 포맷**입니다.

## 구조

```
매일 05:00  daily_scan.py (cron)
              └─ 시세 수집 → 스캔 → SQLite 저장 → 메일 발송(리스트만)

필요할 때   app.py (읽기 전용)
              └─ GET /api/list          현재 보유 종목 (이름·코드·가격·등락률)
              └─ GET /api/chart/<code>  캔들 + 이동평균선
```

app.py에는 스캔을 실행하는 코드가 없습니다. 스캔 버튼도, 진행률 폴링도, 탭도
없습니다. 화면에 뭔가 없어서 이상하다면, 그건 빠진 게 아니라 원래 빼기로
한 것입니다.

## 설치와 실행

준비물은 이전과 같습니다 — 파이썬 3.9 이상, "Add to PATH" 체크.

```
./run_mac.sh          맥/리눅스
run_windows.bat        윈도우 (더블클릭)
```

최초 실행 시 가상환경과 패키지를 자동 설치합니다. 그다음:

1. **먼저 데이터를 채워야 목록이 보입니다.**
   ```
   cd backend
   python daily_scan.py --demo --no-notify
   ```
   데모 데이터로 한 번 채운 뒤 서버를 켜서 화면을 확인하세요.
   실제 시세로 채우려면 `--demo` 를 빼세요 (최초 5년 적재는 1시간 남짓).

2. 서버 실행 후 브라우저에서 **http://localhost:5173**

화면은 왼쪽에 보유 종목 목록, 오른쪽에 차트뿐입니다. "새로고침"은 스캔을
다시 하는 게 아니라 **이미 저장된 결과를 다시 불러오는 것**입니다.

## ver1.1 수정 사항

실제 시세 수집 중 `KeyError: '지수명'` 오류로 멈추는 문제를 고쳤습니다.

**원인**: "최근 영업일이 언제인지" 확인할 때 KOSPI 지수 데이터를 조회해서
마지막 날짜로 역산하는 방식을 썼는데, pykrx가 지수 조회에 쓰는 KRX 웹사이트
쪽 응답 구조가 바뀌면서 이 경로가 먼저 깨졌습니다.

**조치**: 지수 조회를 거치지 않는 pykrx의 전용 함수
(`get_nearest_business_day_in_a_week`)로 교체했습니다. 목적이 정확히
"가장 가까운 영업일 구하기"인 함수라 더 안정적입니다.

## ver1.2 추가 수정

ver1.1에서 바꾼 `get_nearest_business_day_in_a_week()`도 이름과 달리
내부적으로 같은 지수 조회(`get_index_ohlcv_by_date`)를 거친다는 걸
코드를 직접 열어서 확인했습니다. 결국 같은 지점에서 다시 깨졌습니다.

**조치**: 지수 API를 아예 쓰지 않는 방식으로 바꿨습니다. 전종목 수집이
매일 쓰는 것과 같은 평범한 개별 종목 시세 조회(동화약품 000020)로 오늘부터
하루씩 거슬러 올라가며 데이터가 있는 날을 직접 찾습니다. pykrx가 제공하는
"편의 함수"에 기대지 않고, 이미 안정적이라고 확인된 경로만 재사용했습니다.

시장 국면(지수 정배열 여부) 판정에 쓰는 지수 시세 적재는 그대로 두었습니다.
이 부분은 여전히 같은 원인으로 실패할 수 있지만, 실패해도 전체 수집이
멈추지 않고 화면에 "국면 판정 불가"로만 표시되도록 이미 처리돼 있습니다.
핵심 기능(종목 스캔)에는 영향이 없습니다.

## ver1.3 추가 수정 — 지금 겪고 계신 문제

**지수·시가총액·영업일 조회가 전부 동시에 "빈 응답"으로 실패하는 경우.**
이건 함수 하나의 버그가 아니라 KRX 서버가 요청 자체를 거부하고 있다는
신호입니다.

**제가 지난번에 한 실수**: 프로그램을 켤 때 뜨는
`KRX 로그인 실패: KRX_ID 또는 KRX_PW 환경 변수가 설정되지 않았습니다`
라는 메시지를 "무시해도 되는 안내"로 판단해서 화면에서 숨겼습니다.
다시 찾아보니 이게 무시할 게 아니라 원인 그 자체일 가능성이 컸습니다.
메시지를 다시 보이게 했고, 수집 시작 전에 한 번 더 명확한 해결 순서를
안내하도록 고쳤습니다.

**원인은 둘 중 하나입니다. 구분하는 방법도 같이 안내드립니다.**

1. **KRX 로그인이 필요한 경우.** 최근 KRX 서버가 로그인 없는 요청에는
   데이터를 안 주는 경우가 있습니다.
   - 해결: [data.krx.co.kr](https://data.krx.co.kr) 에서 무료 회원가입 후,
     명령창에 아래 두 줄을 입력하고 나서 `daily_scan.py`를 다시 실행하세요.
     ```
     set KRX_ID=본인아이디
     set KRX_PW=본인비밀번호
     ```
2. **네트워크(방화벽·백신·회사망)가 KRX 접속 자체를 막고 있는 경우.**
   이 경우는 코드를 아무리 고쳐도 해결되지 않습니다.
   - 확인 방법: 사용 중인 PC의 **일반 브라우저**로 https://data.krx.co.kr
     을 직접 열어보세요. 정상적으로 사이트가 뜨면 1번(로그인) 문제일
     가능성이 높고, 사이트 자체가 안 뜨거나 보안 프로그램이 막았다는
     경고가 나오면 2번(네트워크 차단)입니다. 이 경우 회사 네트워크가
     아닌 개인 네트워크(휴대폰 테더링 등)에서 한 번 시도해 보시거나,
     IT 담당자에게 data.krx.co.kr 접속 허용을 문의하셔야 합니다.

수집이 실패했을 때 이제는 화면 초반에 `[안내]`로 시작하는 문단이 먼저
나오고, "영업일 목록을 하나도 받지 못했습니다"라는 명확한 오류로
멈춥니다. 예전처럼 몇 단계를 더 지나서야 나오는 "적재된 시세가
없습니다"라는, 원인을 알기 어려운 오류로 끝나지 않습니다.

## 클라우드(GitHub)로 옮기기 — ver2.0

**PC를 켜둘 필요가 완전히 없어집니다.** 매일 새벽 5시(KST)에 GitHub이
알아서 데이터를 받고, 종목을 판정하고, 메일을 보냅니다. 웹 화면도
`https://본인아이디.github.io/저장소이름/` 주소로 언제든 열립니다.

터미널 명령어는 필요 없습니다. 전부 웹사이트 화면에서 클릭으로 합니다.

### 1단계 — GitHub 계정 만들기

이미 계정이 있으면 건너뛰세요. 없다면 https://github.com 에서 무료
가입하세요.

### 2단계 — 새 저장소(repository) 만들기

1. GitHub 로그인 후 오른쪽 위 **+** 버튼 → **New repository**
2. 저장소 이름 입력 (예: `stock-screener`)
3. **Public** 선택 (Private는 유료 플랜에서만 웹 화면 기능이 무료로 지원됩니다)
4. **Create repository** 클릭

### 3단계 — 프로젝트 파일 올리기

**먼저 숨김 폴더가 보이도록 설정하세요.** 이 프로젝트에는 `.github`라는,
점(`.`)으로 시작하는 폴더가 있습니다. 이 폴더 안에 자동 실행 설정이
들어 있는데, 윈도우·맥 모두 점으로 시작하는 폴더를 기본적으로
숨깁니다. 안 보이는 채로 올리면 **그 폴더만 조용히 빠지고, 자동
실행이 아예 만들어지지 않습니다** — 오류 메시지도 없이요.

- 윈도우: 탐색기에서 **보기 → 표시 → 숨긴 항목** 체크
- 맥: 탐색기(Finder)에서 `Cmd + Shift + .` (마침표)

숨김 폴더가 보이는 상태에서, 저장소 화면의 **uploading an existing
file** 링크를 클릭하세요. 압축을 푸신 전체 폴더 안의 내용물
(`backend`, `docs`, `frontend`, `scheduler`, `.github`, `README.md`,
`run_mac.sh`, `run_windows.bat`)을 전체 선택해서 끌어다 놓으면 됩니다.
업로드 후 **Commit changes** 클릭.

**업로드가 끝나면 저장소 화면에 `.github` 폴더가 보이는지 꼭
확인하세요.** 안 보이면 그 폴더만 다시 올리시면 됩니다.

### 4단계 — 로그인 정보를 Secrets에 등록

저장소 화면에서 **Settings → Secrets and variables → Actions → New
repository secret** 로 들어가서, 아래 항목을 하나씩 추가하세요. (이름은
왼쪽 칸, 값은 오른쪽 칸에 그대로 입력)

| 이름(Name) | 값(Value) |
|---|---|
| `KRX_ID` | KRX 정보데이터시스템 아이디 |
| `KRX_PW` | KRX 정보데이터시스템 비밀번호 |
| `SCREENER_SMTP_USER` | 메일 보내는 지메일 주소 |
| `SCREENER_SMTP_PASS` | 지메일 앱 비밀번호(16자리) |
| `SCREENER_MAIL_TO` | 메일 받을 주소 (생략하면 기본값 사용) |

이 값들은 저장소가 공개(Public)여도 **아무도 볼 수 없습니다.** 등록한
사람 본인도 나중에 다시 확인할 수 없고, 새 값으로 덮어쓸 수만 있습니다.

### 5단계 — GitHub Pages 켜기

**Settings → Pages** 로 들어가서 Source를 **Deploy from a branch**,
Branch를 **main**, 폴더를 **/docs** 로 선택하고 **Save**. 1~2분 뒤
`https://본인아이디.github.io/저장소이름/` 주소가 활성화됩니다.

### 6단계 — 첫 실행 확인

**Actions** 탭 → 왼쪽의 **정배열 스크리너 일일 스캔** 클릭 → 오른쪽의
**Run workflow** 버튼으로 지금 바로 한 번 실행해볼 수 있습니다. 5년이
아니라 1년치만 받으므로 로컬보다 훨씬 빨리 끝납니다(수 분~수십 분).
초록 체크가 뜨면 성공입니다. 그 뒤로는 매일 새벽 자동으로 실행됩니다.

## 관찰 후보 (참고용, 정배열 아님) — ver2.1

**정배열 확정 종목이 하루도 안 나오는 날에도**, 단기적으로 관심이 몰리는
종목을 별도로 보여주는 기능입니다. 정배열 리스트와는 **신뢰도가 다른
정보**라, 화면·메일 어디서도 절대 섞지 않고 분리해서 보여줍니다.

### 왜 필요했나

정배열(1군)은 "이미 확정된 추세를 뒤늦게 감지"하는 것입니다. 그래서
시장 전체가 뚜렷한 상승 국면이 아니면 — 예를 들어 2,855종목을 다 뒤져도
정배열 종목이 0개인 날도 있습니다. 이건 기준이 타이트해서가 아니라,
정배열이라는 조건 자체가 시장의 실제 기술적 상태를 정직하게 반영하기
때문입니다.

"그래도 내일 오를 가능성이 조금이라도 있는 종목을 보고 싶다"는 요청에
답하려면, 정배열 조건을 완화하는 게 아니라 **완전히 다른 성격의 신호**가
필요합니다. 그래서 별도 섹션으로 분리했습니다.

### 조건

**두 가지 서로 다른 신호를 봅니다.** 하나만 만족해도 후보에 오르고, 어느 신호로 들어왔는지 `[거래량]` `[스테이지6]` 태그로 표시합니다.

**① 거래량 급증 + 20일선 근접**

| 조건 | 기준 |
|---|---|
| 거래량 급증 | 20일 평균 거래량 대비 **2.5배 이상** |
| 20일선 근접 | 이격도 **±3% 이내** |

**② 스테이지6 (이평선 구조 전환)**

일본 이동평균선 투자법의 '대순환분석'에서 가져온 개념입니다. 원서는
5일(단기)/20일(중기)/40일(장기) 세 이평선의 순서 조합 6가지를
스테이지로 구분하는데, 스테이지6은 **"단기선이 장기선은 이미 넘었지만
중기선은 아직 못 넘은"** 상태로, 상승 전환이 막 시작되는 국면으로 봅니다.

이 시스템은 이평선을 4개(5/20/60/120) 쓰기 때문에 "6단계" 틀을 그대로
가져오지 않고, 스테이지6의 조건만 우리 이평선에 맞게 옮겼습니다. 장기
이평선도 원서의 40일 대신 **60일**을 씁니다 — 국내 시장에서 통상 쓰이는
기간이고, 이 시스템 전체가 이미 5/20/60/120을 표준으로 쓰고 있어
일관성이 맞습니다.

| 조건 | 기준 |
|---|---|
| 이평선 순서 | 5일선 > 60일선 > 20일선 (원서의 6단계를 5/20/60에 맞게 이식) |
| 신선도 | **오늘 처음** 이 순서가 된 종목만 (어제도 같았으면 제외) |

**공통 조건**

| 조건 | 기준 |
|---|---|
| 유동성 | 20일 평균 거래대금 5억 원 이상 (정배열과 동일) |
| 정배열 여부 | **보지 않음** — 하락 추세여도 두 신호 모두 뜰 수 있습니다 |

이미 정배열 리스트(신규 편입/유지)에 있는 종목은 관찰 후보에 중복
표시하지 않습니다. **두 신호가 동시에 뜬 종목을 우선**, 그다음 거래량
배수가 큰 순서로 **상위 20개**까지만 보여줍니다.

설정 위치는 정배열 기준과 같은 `backend/screener.py`의 `CONFIG` 안에
`watch_vol_ratio`, `watch_disparity_band`, `watch_max_items`로 있습니다.
스테이지6은 별도 설정값 없이 기존 5/20/60일선을 그대로 재사용합니다.

### 반드시 아셔야 할 한계

**이 신호는 아직 검증되지 않았습니다.** 정배열 조건은 최소한 "정배열이면
과거 데이터로 봤을 때 어느 정도는 근거가 있다"는 사고 아래 만든 것이지만,
관찰 후보는 백테스트를 거치지 않은 초기 아이디어입니다. 거래량 급증이
다음 날 상승으로 이어질지, 아니면 단순 변동성 확대일 뿐인지는 실제로
확인되지 않았습니다.

화면과 메일에도 이 사실을 계속 표시합니다. **투자 판단의 근거로 쓰지
마시고, 참고용으로만 봐주세요.** 나중에 이 신호도 `backtest.py`로 검증할
계획입니다.

  클릭하면 펼쳐지고, 종목을 클릭하면 차트도 볼 수 있습니다.
